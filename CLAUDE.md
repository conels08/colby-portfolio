## Commands

```bash
npm run dev    # Next.js dev server
npm run build  # production build
npm run start  # serve production build
npm run lint   # ESLint (flat config in eslint.config.mjs)
```

There is no test runner configured. `playwright` is installed as a devDependency but no test suite or test script exists yet.

## Stack

Next.js 16 (App Router) + React 19 + TypeScript, Tailwind CSS v4 (via `@tailwindcss/postcss`, configured through `@theme inline` in `globals.css` — there is no `tailwind.config.*`), Framer Motion, Lucide icons. Server-side: Resend for transactional email, Supabase (`@supabase/supabase-js`) for the newsletter table, Zod for request validation. Deployed on Vercel (Analytics + Speed Insights wired in `src/app/layout.tsx`).

Path alias: `@/*` → `src/*` (see `tsconfig.json`).

## Architecture

### Content is data-driven

`src/data/projects.ts` is the single source of truth for the `Project` type and the `projects` array consumed by the home page, `/work`, `ProjectCard`, `ProjectDrawer`, and `CommandPalette`. To add or change a project, edit this file rather than the page components. Project images live under `public/projects/<Project>/...` and are referenced by string paths from `projects.ts`.

### Theme + HUD mode

`src/components/ThemeProvider.tsx` owns two orthogonal pieces of state: `theme` (`light` | `dark`) and `mode` (`default` | `hud`). HUD mode is a green-on-black "terminal" treatment that overrides the dark/light classes and adds `hud-mode`, `hud-scanlines`, `hud-vignette` to `<html>` plus `hud-body` to `<body>`. The matching CSS variables and `.hud-*` utility classes are defined in `src/app/globals.css`. Both pieces of state are persisted to `localStorage` (`theme`, `mode`).

Note: `toggleTheme` intentionally resets `mode` to `default` — toggling light/dark is the documented way to exit HUD mode (see commit `64b5fa3`).

Consumers must be inside `<ThemeProvider>` (mounted in `src/app/layout.tsx`) and use the `useTheme()` hook, which throws if used outside the provider.

### API routes share a security helper

`src/app/api/contact/route.ts` and `src/app/api/newsletter/route.ts` both:

1. Call `rejectInvalidOrigin(req)` from `src/lib/security.ts` — enforces same-origin via the `Origin` header against `NEXT_PUBLIC_SITE_URL` (default `https://colbynelsen.com`), with a localhost bypass when `NODE_ENV !== "production"`. Also rejects cross-site `Sec-Fetch-Site` values.
2. Call `rejectRateLimited(req, { key, maxRequests, windowMs })` — in-memory per-IP limiter keyed off `x-forwarded-for` / `x-real-ip`, stored on `globalThis.__portfolioRateLimitStore__`. **This is per-instance and not durable** — it resets on cold start and does not work across serverless instances. Acceptable for a low-volume portfolio; revisit before relying on it for anything serious.
3. Validate the body with a Zod schema and silently 200 if the `honey` honeypot field is filled.

Contact emails go out via Resend from `onboarding@resend.dev` to `CONTACT_TO_EMAIL`. Newsletter inserts into the Supabase `newsletter_subscribers` table (columns: `email`, `source`, `status`); duplicate-email errors (Postgres `23505`) are treated as success with `alreadySubscribed: true`. Newsletter notification email is best-effort — a Resend failure is logged but does not fail the request.

### Security headers

`next.config.ts` sets global response headers (`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS) on every route. Add new headers here rather than per-route.

### SEO / metadata

Site metadata, icons, OG/Twitter cards, and JSON-LD (`Person` + `WebSite` schema) live in `src/app/layout.tsx`. OG/Twitter images are dynamic routes (`opengraph-image.tsx`, `twitter-image.tsx`, `_socialCard.tsx`). Sitemap is generated by `src/app/sitemap.ts`. `metadataBase` and the structured-data URLs are hardcoded to `https://colbynelsen.com` — update both if the canonical domain changes. See `SEO.md` for the broader SEO playbook (DNS, GSC, canonical decisions).

## Environment variables

Required for the API routes to function (set in `.env.local` for dev, in Vercel for prod):

- `RESEND_API_KEY` — Resend API key for outbound mail
- `CONTACT_TO_EMAIL` — recipient for contact form (defaults to `colbynelsen@gmail.com` if unset)
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — newsletter persistence (service role; do not expose to the client)
- `NEWSLETTER_NOTIFY_TO` — recipient for new-subscriber notification emails
- `NEXT_PUBLIC_SITE_URL` — used by `rejectInvalidOrigin` to validate request origins

The contact route returns 500 if `RESEND_API_KEY` is missing; the newsletter route returns 500 if either Supabase var is missing.
